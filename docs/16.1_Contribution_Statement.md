# Section 16.1 — Research Contribution Statement

## 1. Project Context & Intellectual Rationale

In high-assurance enterprise computing—particularly in human resources, financial payroll, and legal compliance—relational database management systems (RDBMS) serve as the authoritative system of record. However, the standard Discretionary Access Control (DAC) model deployed across relational databases inherently trusts the superuser (`postgres`, `sysadmin`, or `sa`). A rogue administrator or an external adversary who acquires administrative database credentials possesses the untracked capability to silently execute `UPDATE` or `DELETE` statements against operational tables and historical audit logs.

**Argus** addresses this fundamental trust asymmetry by engineering a cryptographic, tamper-evident audit logging and verification subsystem natively within PostgreSQL 15+. 

---

## 2. Core Contributions

This research and engineering effort delivers four primary contributions to database security architecture:

1. **Native In-Engine Cryptographic Hash Chaining with 2PL Concurrency Safety:**
   We design and implement an atomic, in-engine audit pipeline utilizing PostgreSQL `AFTER` triggers and native `pgcrypto` primitives. By binding chain state transitions to an exclusive row lock (`SELECT ... FOR UPDATE`) on a singleton relational state entity, Argus guarantees strict linear serialization of hash-chained audit events ($O(1)$ amortized marginal write overhead) with zero race-condition forks or deadlocks across concurrent multi-threaded client connections.

2. **Decoupled Asymmetric Checkpointing & External Immutability Anchoring:**
   To overcome the fundamental limitation of internal database logging—where a superuser can execute a "recompute-and-hide" attack by rewriting the table and re-hashing all subsequent entries—Argus introduces a decoupled checkpointing architecture. Intermediate sequence ranges are aggregated and signed using **Ed25519 asymmetric cryptography** via an independent verification daemon and anchored into an out-of-band immutable store (e.g., GitHub private repository or WORM storage).

3. **High-Throughput Parallel Verification Engine with Cross-Segment Continuity:**
   We construct a standalone verification CLI that implements keyset-paginated audit walks ($O(1)$ auxiliary memory). To audit large enterprise audit histories efficiently, we formalize and implement a multi-core parallel verification algorithm utilizing `concurrent.futures.ProcessPoolExecutor`. Each worker verifies the internal cryptographic continuity of an isolated checkpoint segment, followed by a deterministic $O(S)$ sequential boundary check. This architecture achieves a **6.19x speedup** on 8 worker cores, validating 100,000 complete audit records in under 1.9 seconds ($\approx 54,000$ entries/second).

4. **Comprehensive Empirical Evaluation & Attack Validation:**
   We conduct extensive micro-benchmarks and parameter sweeps across scale levels up to 100,000 rows. We formally define and experimentally rehearse six distinct threat scenarios—ranging from application-layer privilege escalation and direct superuser modifications to forged external anchor signatures—demonstrating 100% anomaly detection with zero false negatives.
