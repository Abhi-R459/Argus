# Section 16.7 — Comparison Matrix & Related Work

## 1. Executive Summary & Comparative Positioning

Modern database architectures employ diverse strategies to provide auditability, ranging from passive text-log auditing to full distributed blockchain state machines. Argus occupies a distinctive architectural sweet spot: it delivers **strong cryptographic tamper-evidence and external asymmetric non-repudiation natively inside standard PostgreSQL**, without requiring specialized proprietary cloud database engines, esoteric query languages, or high-latency distributed consensus protocols.

## 3. Deep-Dive Comparative Analysis

### 3.1 Argus vs. Traditional PostgreSQL Logging (pgAudit & pgMemento)
- **pgAudit:** Focuses exclusively on *event notification* rather than *state immutability*. pgAudit emits text records into PostgreSQL server log files (`stderr` or `syslog`). While performant, it offers zero cryptographic protection: any administrator with filesystem access can edit or truncate the log files with standard Unix tools (`sed`, `rm`), leaving no mathematical trace.
- **pgMemento:** Uses PL/pgSQL triggers to maintain schema and data history in relational audit tables. However, pgMemento stores these records as standard relational rows without cryptographic hashing or chain linking. A database superuser can execute `UPDATE pgmemento.audit_table` with impunity. In contrast, Argus computes SHA-256 hash chains on write and anchors signed checkpoints externally, converting stealth tampering into provable anomalies.

### 3.2 Argus vs. SQL Server Ledger
Microsoft SQL Server Ledger (introduced in SQL Server 2022) represents the closest relational precedent to Argus. It computes SHA-256 hashes over row versions organized into a block-level Merkle tree within the SQL Server storage engine.
- **Core Distinction (Signatures vs. Digests):** As verified against Microsoft Learn documentation, SQL Server Ledger exports unsigned cryptographic digests ("database digests") to external storage (e.g., Azure Immutable Blob Storage). An unsigned digest only proves integrity if the transmission channel and storage bucket remain perfectly trusted. Argus advances this design by incorporating **Ed25519 asymmetric digital signatures** directly into each checkpoint. Even if the external anchor repository is compromised, an attacker cannot forge valid signatures without the private key.
- **Independence of Verification:** SQL Server Ledger's verification is typically performed via an in-engine stored procedure (`sys.sp_verify_database_ledger`), meaning the entity performing the verification is the very engine being audited. Argus strictly separates verification into an independent, out-of-process CLI tool that can execute on an auditor workstation with zero dependency on database-internal verification routines.

### 3.3 Argus vs. Distributed Ledgers (Amazon QLDB & Hyperledger Fabric)
- **Architectural Simplicity & Performance:** Hyperledger Fabric and distributed ledgers introduce massive operational complexity: Byzantine fault tolerance (BFT) consensus algorithms, peer node orchestration, smart contract runtimes, and multi-second block commit latencies. This imposes a heavy penalty on write throughput ($\approx 50\text{–}500\text{ ms}$ per transaction).
- **Argus Efficiency:** By recognizing that enterprise applications need tamper-evidence and auditability—not decentralized multi-party Byzantine consensus—Argus avoids consensus overhead entirely. It leverages PostgreSQL's proven Two-Phase Locking (2PL) and Write-Ahead Logging (WAL) engines to achieve sub-millisecond write latencies ($\approx 0.8\text{ ms}$) while providing cryptographic tamper detection equivalent to distributed ledgers.

---

## 4. Conclusion & Architectural Contributions

Argus demonstrates that enterprise-grade tamper evidence does not require sacrificing relational capabilities or migrating to complex, proprietary distributed ledger systems. By marrying PostgreSQL triggers with row-level serialization, Ed25519 signed checkpoints, and independent verification, Argus provides a lightweight, open-source, and verifiable audit architecture for sensitive relational workloads.
